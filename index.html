Lee tres Data Tables (leads, tickets, acciones), calcula los números en nodos simples y solo después pide a una IA que redacte lo que requiere atención. Lee la salida de los otros flujos: las automatizaciones forman un sistema.

  • Bug que encontré: un secreto pegado traía un salto de línea al final y rompía la llamada en silencio. Ahora la ruta limpia cada variable de entorno.
  • Terminado = verificado: envié una aplicación real de prueba, confirmé la fila y los dos correos, y borré la fila de prueba.

Workspace demo

A team workspace with an AI agent, built from scratch around a fictional studio so I can show how I design this kind of product without any real company data. Chat, threads and drafts on the surface; the interesting part is the control flow underneath.

Un espacio de trabajo de equipo con un agente de IA, construido desde cero alrededor de un estudio ficticio para mostrar cómo diseño este tipo de producto sin datos de ninguna empresa real. Chat, hilos y borradores en la superficie; lo interesante es el flujo de control por debajo.

  • React
  • Vite
  • Optimistic UI
  • Idempotency
  • Human-in-the-loop
Decisions & lessonsDecisiones y aprendizajes
  • Human-authorized agent actions. The assistant only proposes; nothing changes until a person approves the exact action.
  • Exactly-once execution. Each proposal carries an execution key. Pressing “Approve again” is blocked and logged, so a double click or a retry can't create the task twice.
  • Sends that survive outages. Messages appear instantly, fail visibly when the network drops and can be retried; a client id stops duplicates.
  • Idempotent import. A fictional Slack export carries external ids; importing it twice adds 0.
  • Honest scope. A front-end simulation of the patterns: no server, and the assistant is rule-based, not an LLM. The page says so.
  • Acciones del agente autorizadas por humanos. El asistente solo propone; nada cambia hasta que una persona aprueba la acción exacta.
  • Ejecución exactamente-una-vez. Cada propuesta lleva una llave de ejecución. “Aprobar otra vez” se bloquea y queda registrado: un doble clic o un reintento no crea la tarea dos veces.
  • Envíos que sobreviven a las caídas. Los mensajes aparecen al instante, fallan de forma visible si cae la red y se pueden reintentar; un id de cliente evita duplicados.
  • Importación idempotente. Una exportación ficticia de Slack trae ids externos; importarla dos veces agrega 0.
  • Alcance honesto. Una simulación front-end de los patrones: sin servidor, y el asistente es por reglas, no un LLM. La página lo dice.

Personal AI OS

A persistent orchestrator-plus-workers agent system on a dedicated always-on machine. Constrained on purpose: the model can only do what a permission policy explicitly allows, and every run leaves an auditable trail.

Un sistema de agentes persistente (orquestador + workers) en una máquina dedicada siempre activa. Con restricciones a propósito: el modelo solo puede hacer lo que una política de permisos permite explícitamente, y cada ejecución deja un rastro auditable.

  • Python
  • Agents
  • Sandboxing
  • Tests
Decisions & lessonsDecisiones y aprendizajes
  • No unrestricted shell. Tools are allowlisted per run; git is default-deny with only local commands permitted; push, pull and clone are blocked.
  • Isolation: workers operate in detached worktrees, so a run can never touch the source checkout.
  • Delegation is explicit: a parent hands work to a worker through a durable, idempotent handoff record, and the run resumes safely after a crash.
  • Verify before trusting: every change is reviewed and its tests run independently. 240+ automated tests.
  • Sin shell irrestricto. Las herramientas se permiten por ejecución; git es default-deny y solo permite comandos locales; push, pull y clone están bloqueados.
  • Aislamiento: los workers operan en worktrees separados, así que una ejecución nunca toca el checkout original.
  • La delegación es explícita: un padre entrega trabajo a un worker mediante un registro de traspaso durable e idempotente, y la ejecución se reanuda de forma segura tras una caída.
  • Verificar antes de confiar: cada cambio se revisa y sus tests se corren de forma independiente. Más de 240 tests automáticos.
