Press & Breathe

A full rebuild of a yoga-teacher-training program's site. The whole chain, verified with a real submission: public application form, database, an n8n automation, and a personalized confirmation email.

Reconstrucción completa del sitio de un programa de formación de profesores de yoga. Toda la cadena, verificada con un envío real: formulario público, base de datos, automatización en n8n y correo de confirmación personalizado.

  • Next.js
  • Supabase
  • n8n
  • Vercel
Decisions & lessonsDecisiones y aprendizajes
  • Locked-down writes. Row-level security is on; applications are inserted only through a server route, never from the browser.
  • Authenticated webhook. The n8n webhook only runs when a shared-secret header matches, so nobody can trigger emails by guessing the URL.
  • Bug I hit: a pasted secret carried a trailing newline and silently broke the call. The route now trims every env var.
  • Done means verified: I submitted a real test application, confirmed the row and both emails, then deleted the test row.
  • Escrituras protegidas. Seguridad a nivel de fila activada; las aplicaciones se insertan solo desde una ruta de servidor, nunca desde el navegador.
  • Webhook autenticado. El webhook de n8n solo corre si un header secreto coincide; nadie puede disparar correos adivinando la URL.
  • Bug que encontré: un secreto pegado traía un salto de línea al final y rompía la llamada en silencio. Ahora la ruta limpia cada variable de entorno.
  • Terminado = verificado: envié una aplicación real de prueba, confirmé la fila y los dos correos, y borré la fila de prueba.

Casa Azul

Internal admin for a wellness venue: bookings, payments and refunds, client history, a calendar, and a finance view for weekly and monthly reporting. The live demo runs on fictional data and blocks writes.

Panel interno para un espacio de bienestar: reservas, pagos y reembolsos, historial de clientes, calendario y vista de finanzas para reportes semanales y mensuales. El demo en vivo usa datos ficticios y bloquea escrituras.

  • Next.js 16
  • TypeScript
  • Supabase
  • Tailwind
Decisions & lessonsDecisiones y aprendizajes
  • Status is derived, not typed. A reservation's state comes from the money received; "cancelled" is the only manual state, and cancelling keeps the payments.
  • Money rules: amounts are always positive and refunds subtract; income is counted by payment date, not by event date.
  • Timezone-safe: dates are plain YYYY-MM-DD strings in Lima time, which avoids the classic UTC off-by-one.
  • Caught by looking: reviewing screenshots I found the income chart never drew its bars (percentage heights collapsed inside flex). Fixed with pixel heights.
  • Demo mode: one switch swaps the data layer for date-relative fixtures and skips auth, so the same UI is public without exposing anything real.
  • El estado se deriva, no se escribe. El estado de una reserva sale del dinero recibido; "cancelada" es el único estado manual y conserva los pagos.
  • Reglas de dinero: los montos son siempre positivos y los reembolsos restan; el ingreso se cuenta por fecha de pago, no de evento.
  • Zona horaria segura: fechas como texto YYYY-MM-DD en hora de Lima, evitando el clásico desfase UTC.
  • Detectado mirando: al revisar capturas vi que el gráfico de ingresos nunca dibujaba las barras (alturas en % colapsadas en flex). Corregido con alturas en píxeles.
  • Modo demo: un interruptor cambia la capa de datos por fixtures relativos a la fecha y omite el login; la misma UI es pública sin exponer nada real.

MotoYa

A prototype of a mototaxi ride-hailing marketplace for small Andean towns: the rider proposes the price and nearby drivers accept or counter. Rider and driver phones stay in sync through a whole trip, from offer to payment and rating.

Prototipo de un marketplace de mototaxis para pueblos andinos: el pasajero propone el precio y los conductores cercanos aceptan o contraofertan. Los teléfonos de pasajero y conductor se mantienen sincronizados durante todo el viaje, de la oferta al pago y la calificación.

  • React
  • Vite
  • State machine
  • SVG maps
Decisions & lessonsDecisiones y aprendizajes
  • One state machine, two phones. A single reducer drives both apps, so what the driver taps is what the rider sees. No backend needed to feel like a marketplace.
  • Guided tour. A script that "taps" both phones on its own, made for pitches; any real tap on the screen takes over.
  • Real geometry. The tuk-tuk follows the actual SVG route, so pickup, trip progress and ETA are computed from the path, not faked with a timer.
  • Honest scope. The page states what is real (the full flow) and what is missing to be a product: real map, matching backend, driver verification, payments.
  • Started as a single-screen mockup and I rebuilt it as a product page once it felt "beta": the rider-only flow hid half the marketplace.
  • Una máquina de estados, dos teléfonos. Un solo reducer maneja ambas apps: lo que toca el conductor es lo que ve el pasajero. Sin backend, pero se siente como un marketplace.
  • Recorrido guiado. Un guion que "toca" ambos teléfonos solo, pensado para pitches; cualquier toque real toma el control.
  • Geometría real. El mototaxi sigue la ruta SVG real: recogida, progreso y ETA salen del trazado, no de un temporizador falso.
  • Alcance honesto. La página dice qué es real (el flujo completo) y qué falta para ser producto: mapa real, backend de emparejamiento, verificación de conductores, pagos.
  • Empezó como una maqueta de una pantalla y la reconstruí como página de producto cuando se sintió "beta": el flujo solo del pasajero escondía la mitad del marketplace.

Personal AI OS

A persistent orchestrator-plus-workers agent system on a dedicated always-on machine. Constrained on purpose: the model can only do what a permission policy explicitly allows, and every run leaves an auditable trail.

Un sistema de agentes persistente (orquestador + workers) en una máquina dedicada siempre activa. Con restricciones a propósito: el modelo solo puede hacer lo que una política de permisos permite explícitamente, y cada ejecución deja un rastro auditable.

  • Python
  • Agents
  • Sandboxing
  • Tests
Decisions & lessonsDecisiones y aprendizajes
  • No unrestricted shell. Tools are allowlisted per run; git is default-deny with only local commands permitted; push, pull and clone are blocked.
  • Isolation: workers operate in detached worktrees, so a run can never touch the source checkout.
  • Delegation is explicit: a parent hands work to a worker through a durable, idempotent handoff record, and the run resumes safely after a crash.
  • Verify before trusting: every change is reviewed and its tests run independently. 240+ automated tests.
  • Sin shell irrestricto. Las herramientas se permiten por ejecución; git es default-deny y solo permite comandos locales; push, pull y clone están bloqueados.
  • Aislamiento: los workers operan en worktrees separados, así que una ejecución nunca toca el checkout original.
  • La delegación es explícita: un padre entrega trabajo a un worker mediante un registro de traspaso durable e idempotente, y la ejecución se reanuda de forma segura tras una caída.
  • Verificar antes de confiar: cada cambio se revisa y sus tests se corren de forma independiente. Más de 240 tests automáticos.

Winter Arc

A 120-day personal fitness PWA: weight and body composition, macros, training volume, PRs and estimated 1RM. Built mobile-first; the live demo runs a fictional person on day 81 of the arc.

Una PWA personal de fitness de 120 días: peso y composición corporal, macros, volumen de entrenamiento, PRs y 1RM estimado. Pensada primero para móvil; el demo en vivo corre con una persona ficticia en el día 81 del arco.

  • Next.js
  • TypeScript
  • Supabase
  • PWA
  • Vitest
Decisions & lessonsDecisiones y aprendizajes
  • Pure domain logic. Scoring, XP, weekly volume and strength (Epley 1RM) are plain functions with unit tests, separate from the UI and the database.
  • Honest numbers. The app labels an estimated 1RM as an estimate, and the calorie target as orientative: the week is what counts.
  • Demo without a database. A small in-memory stand-in for the Supabase queries feeds the same pages and components, and every write is blocked, so the real code path is unchanged.
  • Lógica de dominio pura. Puntaje, XP, volumen semanal y fuerza (1RM de Epley) son funciones simples con tests unitarios, separadas de la UI y la base de datos.
  • Números honestos. La app rotula el 1RM estimado como estimación y la meta calórica como orientativa: lo que cuenta es la semana.
  • Demo sin base de datos. Un reemplazo en memoria de las consultas a Supabase alimenta las mismas páginas y componentes, y toda escritura está bloqueada; el camino real no cambia.
